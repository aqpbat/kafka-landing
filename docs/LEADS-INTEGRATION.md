# Отправка форм в Telegram через kafka-bot

Задание для агента, работающего с сайтом. Цель: формы «Получить демонстрацию» и «Отправить расчёт менеджеру» должны отправлять заявку в сервис `kafka-bot`, а он пересылает её в Telegram-чат отдела продаж.

Сервис уже работает в бою, со стороны бота ничего делать не нужно. Работа только в этом репозитории.

## Сервис kafka-bot

- Код: `../kafka-bot` (GitHub `aqpbat/kafka-landing-bot`). Полное описание API и решений по безопасности: `../kafka-bot/AGENTS.md`.
- Адрес: `https://kafka-bot-production.up.railway.app`. Позже, возможно, будет свой домен вроде `api.kafka.kz`, поэтому адрес не хардкодить, а брать из переменной окружения `PUBLIC_LEAD_API` (полный URL до `/lead`). Значение по умолчанию: `https://kafka-bot-production.up.railway.app/lead`.
- Разрешённые источники (CORS, `ALLOWED_ORIGINS`): только `https://kafka.kz` и `https://www.kafka.kz`. С `localhost` запрос получит 403. Для локальной проверки попросите пользователя временно добавить `http://localhost:4321` в `ALLOWED_ORIGINS` на Railway (это переменная сервиса kafka-bot) или проверяйте с подменой `fetch` в playwright.
- Каждая успешная заявка уходит в реальный чат продаж. Не отправляйте тестовые заявки без согласия пользователя; если отправляете, ставьте в имя «ТЕСТ».

## Запрос

`POST <PUBLIC_LEAD_API>`, заголовок `Content-Type: application/json`, тело:

```json
{
  "form": "demo",
  "name": "Айгерим",
  "phone": "+7 747 555 76 04",
  "venue": "Кафе «Тандыр»",
  "points": "2–3",
  "modules": ["AI-бот", "CRM"],
  "comment": "",
  "page": "/pricing",
  "utm": { "utm_source": "instagram" },
  "website": "",
  "elapsed": 12500
}
```

| Поле | Что передавать |
|---|---|
| `form` | `demo` — форма демо; `pricing` — расчёт с `/pricing`; `partner` — форма на `/partners`. Другое значение сервер превращает в `demo`. |
| `name` | Обязательно. До 100 символов. |
| `phone` | Обязательно. Номер Казахстана в любом формате (`+7…`, `8…`, 10 цифр). Сервер нормализует сам. |
| `venue` | Название заведения, до 150 символов. |
| `points` | Выбранная кнопка «Количество точек» (строка, как на кнопке). |
| `modules` | Выбранные чипы «Какие модули интересны» (массив строк, до 20). Для `pricing` — модули из конструктора тарифа. |
| `comment` | Свободный текст до 1000 символов. Для `pricing` сюда стоит положить сводку расчёта: тариф, итоговая сумма. |
| `page` | `location.pathname`. |
| `utm` | Метки `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term` из URL первого входа. Сохраните их в `sessionStorage` при загрузке страницы, иначе они потеряются при переходе на другую страницу. Остальные ключи сервер отбрасывает. |
| `website` | **Ловушка для ботов.** Скрытое текстовое поле в форме, которое человек не видит и не заполняет: вне экрана, `tabindex="-1"`, `autocomplete="off"`, `aria-hidden="true"`. Не `type="hidden"` и не `display:none` — простые боты такие пропускают. Отправлять его значение как есть. |
| `elapsed` | **Обязательно, числом** (не строкой): миллисекунды с момента показа формы до отправки. Если поля нет, оно не число или меньше 3000, сервер молча считает запрос спамом: отвечает `200 {ok:true}`, но в чат ничего не уходит. Это главный способ сломать интеграцию незаметно. |

Других полей не добавлять: сервер их отбрасывает.

## Ответы

| Статус | Тело | Что показать пользователю |
|---|---|---|
| 200 | `{ ok: true }` | Состояние «Заявка отправлена, менеджер свяжется с вами». |
| 422 | `{ ok: false, error: "invalid_phone" }` или `"invalid_name"` | Ошибка у соответствующего поля. |
| 429 | `{ ok: false, error: "too_many_requests" }` | «Слишком много заявок, попробуйте позже или напишите в WhatsApp». Лимит: 5 заявок за 10 минут с одного IP. |
| 502 | `{ ok: false, error: "delivery_failed" }` | «Не удалось отправить, напишите нам в WhatsApp» и кнопка WhatsApp. |
| 400, 403, 413, 415, сеть, таймаут | — | То же, что при 502. |

WhatsApp: `https://wa.me/77475557604` (ссылка с готовым текстом уже есть в макетах, `id="wa"` на главной).

Таймаут на стороне сайта — около 15 секунд (`AbortSignal.timeout`). Пока запрос идёт, кнопка заблокирована и показывает «Отправляем…», чтобы не было двойных заявок.

## Что сейчас на сайте

- Форма демо скопирована в 8 артбордов: `Main`, `Mobile`, `Products`, `Integrations`, `IntegrationRkeeper`, `Cases`, `Pricing`, `Partners` (`design/project/*.dc.html`). Общую правку нужно повторить во всех (см. `AGENTS.md`).
- Разметка формы (`Main.dc.html`, около строки 631): `<form>` без `action`; поля `Имя`, `Название заведения` (`type="text"`), `Телефон` (`type="tel"`) — **без `name`/`id`** и не связаны со state.
- «Количество точек» — кнопки из `pointOpts`, выбранное значение в `state.points` (по умолчанию `'2–3'`). «Какие модули интересны» — чипы из `interestChips`, выбранные в `state.interests` (объект `{ label: true }`).
- Кнопка «Получить демонстрацию» — `type="button"`, поэтому событие `submit` сейчас вообще не возникает. В `src/lib/dc/runtime.ts:76` любой `submit` гасится (`preventDefault`) с комментарием «Forms have no backend yet».
- На `/pricing` кнопка «Отправить расчёт менеджеру» (`Pricing.dc.html`, около строки 240) — просто ссылка `href="#demo"`. Выбранный тариф и модули конструктора (`state.mods` и др. в классе `Component`) никуда не передаются.
- Ссылка «политикой обработки персональных данных» под формой ведёт на `#` — документа пока нет. Не блокирует работу, но упомяните пользователю.

## Как подойти

Ограничения формата `.dc.html` — в `AGENTS.md` этого репозитория: в логике артборда нет `import` и внешних запросов, UI нельзя строить через `innerHTML`. Поэтому сетевой код лучше держать в `src/` (механика сайта), а в артбордах — только разметку, состояние и вызов. Возможный вариант:

1. Общий модуль в `src/lib/` (например, `lead.ts`): сбор UTM, отметка времени показа формы, `fetch` с таймаутом, разбор ответа в одно из состояний `sent | invalid_phone | invalid_name | rate_limited | failed`.
2. Рантайм (`runtime.ts`) отдаёт эту функцию логике артборда (например, через глобальный объект или метод на `DCLogic`), а на канвасе claude.ai, где модуля нет, вызов безопасно ничего не делает.
3. В артбордах: поля формы связать со state (или читать по `name` в обработчике), кнопку сделать `type="submit"` или повесить обработчик, добавить ловушку `website`, состояния «отправляется / отправлено / ошибка» и подсветку ошибок полей. Клиентская проверка телефона: 10 цифр после `+7`/`8`, первая цифра 7.
4. `/pricing`: либо отправлять расчёт сразу с `form: "pricing"`, либо переходить к форме `#demo` с подставленными тарифом и модулями. **Какой вариант — спросить пользователя.**
5. Если в `docker/nginx.conf` появится CSP, в `connect-src` нужно разрешить адрес бота.

Выбор конкретной механики — за вами, но сначала покажите пользователю план и уточните поля формы (в `docs/PLAN.md` подключение отложено «до обсуждения полей формы»).

## Проверка

- `npm run build`, `npm run check`.
- Скриншоты формы в состояниях «пусто / отправляется / отправлено / ошибка» на 1440 и 390 px (`scripts/shot.mjs`).
- Playwright: перехватить запрос к `PUBLIC_LEAD_API` (`page.route`) и проверить тело — `elapsed` число не меньше 3000, `website` пустой, `phone`, `name`, `points`, `modules`, `page`, `utm` на месте; прогнать ответы 200, 422, 429, 502.
- Живую отправку в чат делать только с согласия пользователя, с «ТЕСТ» в имени и с разрешённого источника.
- По завершении отметить пункт в `docs/PLAN.md` (раздел «3. Боевая готовность») и убрать из `AGENTS.md` фразу «Формы пока никуда не отправляются».
